# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Rail Narrator is a Linux desktop app (C# / .NET 10, Avalonia 12, SkiaSharp) that reads a PDF aloud, highlights the passage being spoken in the original document, and follows the reading position. PDF rendering, layout, reading order and OCR come from [RailReaderCore](https://github.com/sjvrensburg/RailReaderCore), consumed as NuGet packages pinned to 0.94.0 — Core cannot be modified here; write an application-side adapter instead of a second PDF stack. Core's source is public, so read it at the pinned tag instead of decompiling the package (`gh api "repos/sjvrensburg/RailReaderCore/contents/<path>?ref=v0.94.0" --jq .content | base64 -d`): its comments state preconditions the adapter depends on. A request for a change in Core goes to that repository's issues.

There is no separate lint step: `TreatWarningsAsErrors` is on for every project except `RailNarrator.App`, whose Avalonia XAML compiler warnings (AVLN…) are not turned into errors. The App is still expected to build with 0 warnings: after XAML changes, check the raw output of `dotnet build src/RailNarrator.App -c Release --no-incremental` (through `rtk proxy` on a machine where rtk filters command output), since an incremental build skips unchanged XAML and a filtered summary can hide AVLN lines. Avalonia 12 obsoleted `Watermark`; use `PlaceholderText`.

The local build and test run is the check before a pull request. `.github/workflows/packages.yml` runs for pull requests to `main`: on Windows it builds, tests, packages, and installs, runs and uninstalls the installer, because Windows cannot be checked here; on Ubuntu 22.04 it builds the Linux archive and AppImage as a release does and runs the AppImage. `.github/workflows/release.yml` makes a release from a `v*` tag: the tag must equal `v` + `VersionPrefix` and `docs/releases/<tag>.md` must exist (it is the release notes); Linux is built on Ubuntu 22.04 and fails if a bundled library needs glibc newer than 2.35 (Phonon's, built on this Fedora machine, needs 2.43, so never upload a locally built Linux archive). A release publishes the Linux archive, `rail-narrator-x86_64.AppImage` and its `.zsync` (a stable name: the AppImage's update information points at `latest`), the Windows zip and `rail-narrator-setup-x64.exe` (`installer/rail-narrator.iss`; never change its `AppId`). Add a `<release>` to `packaging/io.github.sjvrensburg.RailNarrator.metainfo.xml` for each version. All carry `LICENSE`, `THIRD-PARTY-NOTICES.txt` (`packaging/`, keep it in step with the bundled packages), `licenses/`, and `install-phonon.sh` (`tools/setup-phonon.sh` with `PHONON_MODEL_ONLY` defaulting to 1; `packaging/common.sh`). The README is for readers; build, layout and release detail is in `docs/development.md`. Work goes on a `feat/`, `fix/`, `docs/` or `chore/` branch and is merged by pull request.

Opt-in integration tests do nothing unless their environment is set. Most are reported as Skipped, but the Kokoro tests in `ProviderTests` and the real-runtime tests in `PhononProviderTests` return early and are reported as Passed, so a green run does not show that either engine spoke. `docs/status.md` counts those as opt-in (four of Phonon, one of Kokoro with durations), so its totals differ from the runner's by five.

## Architecture

Read `docs/next-steps.md` for the current state, the work in progress and the open product decisions; `docs/testing-real-world.md` for running the real models, GUI and audio (headless compositor, XTEST input, isolated XDG dirs, checking the sink is quiet before playing). For the design read `docs/architecture.md`; ADRs in `docs/decisions/` record the measurement behind each decision, and `docs/status.md` separates what is *verified* from what is merely *implemented*. `docs/word-highlighting.md` covers the MFA setup and alignment failure modes. The original product brief is `rail-narrator-coding-agent-prompt.md` (repo root), with its research baseline in `docs/Rail Narrator implementation investigation.md`; consult them for scope questions, but the ADRs and code record where the project has since deviated.

### The central idea: three representations, two separate mappings

PDF source (text + geometry in page points), the narration script (what is actually spoken, after normalisation and maths paraphrase) and the audio timeline (samples at the provider's rate) do not share words, positions or lengths. The design never indexes one into another directly:

```
audio sample position ──► spoken script range     (CueScheduler / NarrationTimeline, TimedCue)
spoken script range   ──► original source anchors  (SourceMap, SourceLink, TransformedText mappings)
```

Any text transform must carry a `TextMapping` back to its source (`Normalisation.cs`); collapsing or dropping mappings makes highlights cover the wrong text silently.

### Pipeline

```
RailReaderExtractionSource ─► ExtractionSnapshot ─► ReadingUnitBuilder ─► ReadingUnit[]
   ─► NarrationPlanner ─► NarrationPlan (source-linked segments)
   ─► NarrationCoordinator ─► ITtsProvider clips (+ optional IForcedAligner word cues)
   ─► AudioPlaybackEngine media clock ─► ActiveCue ─► overlays + follow camera
```

`MainViewModel.LoadDocumentAsync` is the place where this chain is assembled end to end; `ServiceRegistry` (`src/RailNarrator.App/Composition/`) is the hand-written composition root — no DI container, by design.

### Layering

`RailNarrator.Domain` references nothing (no Skia, ONNX, HTTP or RailReaderCore) and holds the contracts plus all narration logic. Every external capability is a port in `Domain/Ports.cs` (and `IAudioTransport` in `Coordination.cs`), implemented outward:

- `Pdf` — RailReaderCore adapter: extraction, coordinate transforms, hit-testing, overlay rendering
- `Speech` — `ITtsProvider` (Phonon and Kokoro in-process, ZONOS3 HTTP sidecar, fake), `MfaForcedAligner` driving the embedded `alignment_worker.py`, PCM/WAV codecs
- `Audio` — PortAudio callback output, resampler, WSOLA speed change, presented-frame media clock; `FakeAudioOutputDevice` for tests
- `Inference` — maths interpretation, transcription and verbalisation over an OpenAI-compatible endpoint or Claude (`ClaudeMath.cs`, Anthropic's .NET SDK), `MathResponseValidator`, `LocalLatexSpeaker` fallback, and the formula model in-process on ONNX Runtime (`FormulaModel.cs`)
- `Infrastructure` — XDG paths, settings, disk caches, model manifest/downloader, sidecar lifecycle
- `App` — Avalonia views and view-model, Skia-backed `PdfSurface`

New external dependencies go behind a port in Domain so domain tests keep running with no hardware or models. `tests/RailNarrator.TestFixtures` supplies synthetic PDFs (generated with Skia, known geometry) and synthetic narration shared by the suites. The App has no test project: view logic that needs a test sits in a project below it (`ViewZoom` and `PageRasterSource` are in Pdf and tested there), and the rest is checked by driving the GUI as `docs/testing-real-world.md` describes.

### Invariants that span files

- **`NarrationCoordinator` is the single authority for playback state.** Camera, overlays, transcript cursor and progress read from it; nothing else runs its own reading clock.
- **Lock order: never call the transport while holding the coordinator lock, and never raise an engine event while holding the engine lock.** `NarrationCoordinator` reads `_audio.*` before `lock (_gate)`; `AudioPlaybackEngine.SetState` is called outside `lock (_gate)`. Breaking either half deadlocks the UI thread during playback (`CoordinatorLockingTests`, `EngineLockingTests`).
- **Painting never renders a page and never calls PDFium.** Core serialises all PDFium work behind one process-wide lock (`PdfiumGate`), which extraction, OCR and maths crops hold for long stretches. `PdfSurface.Render` only draws rasters that `PageRasterSource` (Pdf project, one worker thread, latest request wins, tiled and cancellable) has already produced: the sharp page, else a stand-in (another zoom, a 72 dpi preview), else blank paper. Page sizes come from the source's array, not `IPdfService.GetPageSize`. Likewise `MainViewModel.LoadDocumentAsync` runs its work on the thread pool and only awaits and reports. A render, a hash or a model start-up on the UI thread shows up as "frame gap" lines in the `RN_FOLLOW_LOG=1` log.
- **Fit-width is a mode, not a number** (`ViewZoom`, Pdf project). While it is on, the zoom is re-derived when the page shown or the reading area's width changes (pages differ in size); a zoom the reader chose turns it off and survives page turns, resizes and the next launch (`FitWidth`, `PreferredZoom` in settings). Do not re-fit from a resize or a page change unconditionally.
- **The transcript list seeks through its `SelectedIndex` binding only.** Do not add a `SelectionChanged` handler: the selection also changes when it follows the audio and on restore, and a seek plays.
- **A request to read ends a pause in following.** Browsing (scroll, drag, page turn) suspends the camera and a timer resumes it; `GoToSegmentAsync` (Next, Previous, Replay, a click, the script list), a Play from a stop and a newly loaded plan clear the suspension at once. Resuming from Pause does not: the reader may have paused to look at something.
- **Generation token.** Document change, seek, script edit and voice change advance it; every in-flight job captures its generation and stale results are dropped. UI handlers also compare `snapshot.Generation` / `cue.Generation` to `Coordinator.Generation` before acting. The coordinator's own operations obey it too: each awaits the transport's stop, and the application does not await a voice change, so an operation that finds itself overtaken after an await stops there. Waiting for a passage (`WaitForSegmentAsync`) uses the caller's token linked with `GenerationToken(generation)`, cancelled by `AdvanceGeneration`: a seek's own synthesis must stop when a newer seek overtakes it, or an engine that speaks one passage at a time works through every overtaken seek first. `StartPreparation` refuses an older generation (starting it would cancel the newer one's lookahead), a voice change discards prepared clips before it awaits, and a plan load takes a fresh generation when it installs its plan.
- **The engine's operations run in order.** `AudioPlaybackEngine` holds `_operations` (a `SemaphoreSlim`, not `_gate`) across `StopAsync`, `LoadAsync`, `PauseAsync`, `SeekAsync`, `SetPlaybackRateAsync` and `QueueNextAsync`, and `StopWriterAsync` returns only when no writer runs, including one another call is still stopping. Without that, the first of two quick seeks finished its stop after the second had loaded and played, and emptied the engine under it. Its events are raised while `_operations` is held, so a subscriber must not wait on the engine synchronously (the coordinator does its work on `Task.Run`). Decoding, resampling and time-stretching a clip (a tenth of a second or more for a long passage) run on the thread pool and outside `_gate`, which the window takes every frame to read the position: the coordinator's awaits often all complete at once (Play with the passage prepared), so work left on the caller's thread ran on the UI thread and froze the window.
- **Media position is presented frames, not wall time.** `AudioPlaybackEngine` derives it from PortAudio callback DAC timestamps; underrun silence consumes no content; `outputLatency` is reported but not subtracted again (ADR-0003). Cue samples are in the clip's own `AudioTimebase`, never device frames. Gapless: the next prepared passage is queued with `IAudioTransport.QueueNextAsync` and written behind the current clip; the engine switches clock and segment only when the boundary frame is *presented* and raises `ClipAdvanced` (not `ClipCompleted`), which the coordinator treats as an advance without a load. Anything that changes a queued passage's words must call `ClearQueuedAsync`.
- **No invented timings.** Word highlighting requires complete, validated forced-alignment evidence; otherwise fall back to whole-sentence (and always whole-equation) cues with a stated reason. Never interpolate by character count (ADR-0004). Alignment is off the playback path: a passage plays once synthesised and its word timing attaches when it arrives (`AlignInBackground`), matched to the held clip by asset id rather than by generation (a Play advances the generation without changing the audio); don't make playback wait for it again. The camera obeys the same rule: a cue with no timing inside it that crosses a page break is framed on the page holding most of it (`SourceMap.FramingPage`, by highlighted area) and held; it does not switch page at a guessed moment, and it does not sit on the first page while the equation overleaf is read. A word the dictionary lacks gets a pronunciation in the worker (acronyms spelled from the dictionary's letter names, the rest from the G2P model) and is still forced-aligned; `<unk>` is never accepted. `SpokenWord.Tokenize` is the one tokeniser for script offsets and aligner words; change it, or the worker protocol, and bump the worker revision in `MfaForcedAligner`.
- **Maths is interpreted during playback, not at load** (`MathMode.Interpret`, the default). The planner leaves display equations and `ContainsMaths` sentences as `ScriptProvenance.PendingInterpretation` holding their fallback (announcement / verbatim sentence); the coordinator resolves them through `ISegmentResolver` (`MathInterpretationResolver` → `IMathInterpreter`) just before synthesis and in a background loop up to `InterpretAheadSegments` ahead, keyed by plan header so a seek neither cancels nor duplicates a model call. Interpreted text is linked to the whole passage and never word-aligned. An unfinished prose unit followed by a display equation is one passage (`NarrationPlanner.LeadsIntoEquation`). Cached answers skip validation, so change `MathInterpretationPrompt` *or* `SpokenMathsValidator` → bump `MathInterpretationPrompt.Version`. Thinking follows `MathThinking` (default `EquationsOnly`: display equations and lead-ins only); a thinking answer cut off at the token limit is retried once with thinking off. A refused interpretation goes to `IMathReader` (the same model transcribes the crop to LaTeX, `LocalLatexSpeaker` reads it ClearSpeak-style) and becomes a labelled `LocalRule` segment; phrasing changes in `LocalLatexSpeaker` → bump `LocalLatexSpeaker.Version`, transcription-prompt changes → bump `MathTranscriptionReading.PromptVersion`. Play pre-rolls: the coordinator waits for `PreRollSeconds` of ready narration ahead, capped at `PreRollTimeoutSeconds`. Page crops come from PDFium as 3-byte RGB (`RenderCropPngAsync` converts to RGBA); a crop failure is a passage warning, never swallowed.
- **No LaTeX reaches a speech engine.** Interpreted maths may keep notation only as spoken words ("sigma t squared", "x sub t"), never as symbols, and not as most of the answer (`SpokenMathsValidator`, prompt v4: plain language first, notation where the model is unsure; the reader's choice). Model output passes `MathResponseValidator`; on failure or with no verbaliser the segment becomes an explicit "could not be read reliably" announcement, or the labelled `LocalRule` reading.
- **A speech engine may time its own words** (ADR-0013), beside the aligner: Phonon from the attention head that follows its text (`AttentionWordTiming`, `TimingProvenance.ModelAttention`; layer 3 head 0 of `phonon-31m-en`, by the model's signature, read through `ptts_speak_aligned`, which exists only in a library built with `tools/phonon-word-timing.patch`), Kokoro from the `durations` output of its timestamped export (`PhonemeWordTiming`, `NativeDuration`; that export names its ids `input_ids`, so it runs in `KokoroSessionRunner`, never KokoroSharp's engine). A provider returns word cues whose ranges are `SpokenWord.Tokenize` tokens of the text it was given; the coordinator maps them to the script (`ToScriptWords`) and drops them for a passage that does not speak its source word for word. `WordTimingSource` (setting `WordTiming`) says whether the engine's timing stands or the aligner replaces it (`EngineTimingStands`); a passage the engine could not time still goes to the aligner. The constants are measured against MFA and the refusals are part of the method (engine text and script compared letter by letter, the head must reach the end, a compound is split only where its part's phonemes end): do not loosen one to "get a timing". Change the recipe → bump `AttentionWordTiming.Version` or `KokoroTtsProvider.PhonemeTimingVersion`, which are in the audio's revision. The "no invented timings" rule is unchanged: these are read from the model, never interpolated.
- **The engine's text is not the script.** At synthesis the coordinator gives the engine `LetterNames.ForSpeech(segment.SpokenText)`: a letter standing alone as a symbol is written as its name ("eh sub tee"), because an engine reads a lone "a" as the article and slurs runs of letters. `SpokenText`, source links, cache keys' text and the aligner's words stay as written, and a provider's own timings are mapped back (`SpeechForm.ToScript`). The names were chosen by what Phonon and Kokoro say ("ay" is "eye" to Kokoro); change them or the rules for "a" → bump `NarrationVersions.ProsePipeline`, which keys the audio.
- **An equation's number is not part of the equation.** Heron has no class for it and leaves it in the block; `EquationLabel` (used in `ReadingUnitBuilder.MakeUnit`) drops a parenthesised number standing apart at a display equation's edge, so the unit's text, its highlight, the formula model's crop and the text-layer check are without it. Geometry decides, not text order: the text layer puts a label in the middle of a multi-line equation.
- **Offsets are UTF-16 and typed** (`TextOffsetUnit`, `TextOffsets`); anchors are single-page with disjoint rectangles and are stamped with `ExtractionIdentity`. `PageRect.UnionAll` is for camera framing only, never highlight geometry.
- **Word boundaries: the text layer proposes, geometry confirms** (ADR-0005). Neither is trusted alone — ink gaps split "2017" at a tabular 1 and hide the space after an "f"; the text layer can hold phantom whitespace inside words. Control characters in page text are not noise: they are unmapped ligature glyphs (`UnmappedGlyphResolver`) or PDFium's line-end hyphen marker (U+0002).
- **The layout model is Docling Heron when installed** (ADR-0008), chosen by `LayoutModelResolver` (setting `LayoutAnalyzer`: `heron`, `pp-doclayout-v3`, `none`, else automatic) and built with Core's `LayoutAnalyzerFactory`: FP32 on the GPU, INT8 on the CPU, XY-cut++ order. Heron has no reference class, so `ReferenceSections` labels the prose under a References heading when no block is already a reference; keep that, or a bibliography is read aloud.
- **Blocks are sorted into reading order before Core's post-processing.** `BlockPostProcessor.PostProcess` expects reading order and renumbers by list position when it removes a duplicate block; a model with its own order (PP-DocLayoutV3) returns blocks by confidence with the order in a field. Every analyzer's blocks therefore go through a resolver first (`ModelOrderResolver` or `XYCutPlusPlusResolver`), as in Core's `AnalysisWorker`. Skipping it for a model "that already has an order" read pages in confidence order.
- **Layout roles decide when a model supplied them** (`ExtractionSnapshot.HasSemanticRoles`). The geometric display-maths and running-element heuristics are the fallback for the model-free analyzer, which labels every block Text; running them over a model's Text blocks turned prose lines into "equations". A layout model takes a raster at exactly its `Capabilities.InputSize`. Inline maths never becomes a unit of its own: it flags its sentence (`ReadingUnit.ContainsMaths`). Tables and algorithms are one unit each, planned as a `StructureAnnouncement`. Contents are not read: `ContentsPages` (used in `ReadingUnitBuilder.Build`, option `SkipContents`) skips pages of entries led to a page number and lists of figures or tables under their heading. First-page front matter is skipped below the level of a block, so a block that also holds the title or the authors keeps them: affiliations and the correspondence address by line (`ReadingUnitBuilderOptions.SkipAffiliations`), article metadata by reading unit (`SkipArticleMetadata`).
- **Caching is per stage** (`Domain/Caching.cs`), each key folding in exactly the inputs that affect that stage. When changing output-affecting logic, bump the matching version constant — `ExtractorVersions.Current`, `NarrationVersions.{MathPrompt,LocalMathReader,ProsePipeline}`, or the worker revision in `MfaForcedAligner` — or stale cached snapshots/plans/audio/timings will be reused. `ProsePipeline` also covers unit building and what is skipped (`Units.cs`), not only normalisation: the plan id and the audio key carry it. A Core package upgrade needs no bump, because `ServiceRegistry.ExtractionBackendFingerprint` folds the RailReader assembly versions into the extraction key. Maths has a second, separate layer: cached model answers are keyed by the interpreter's `Revision` (`MathInterpreter.cs`: `MathInterpretationPrompt.Version`, `MathTranscriptionReading.PromptVersion`, `LocalLatexSpeaker.Version`), not by `NarrationVersions` — bumping one does not invalidate the other. The formula model's transcriptions are cached there too, by its `Revision` and the crop's hash. Extraction snapshots are cached on disk by `CachingExtractionSource` (Infrastructure); the app extracts through `ServiceRegistry.CachedExtraction` and keeps `Extraction` for rendering and hit-testing.
- **Layout on the GPU goes through `LayoutAnalyzerConstruction` only** (ADR-0006). Core's WebGPU switch is a static `LayoutAnalyzer.ConfigureSession` hook, so every `LayoutAnalyzer` construction, CPU ones included, holds `WebGpuAccelerator.ConstructionLock` for enable → construct → disable. Never `new LayoutAnalyzer(...)` elsewhere. The device (`LayoutDevice.Id`) is part of the extraction cache key: CPU and GPU give the same reading but not byte-identical geometry. A GPU that fails at start-up or mid-document hands over to the CPU with a page warning; OCR stays on the CPU.
- **Kokoro on the GPU goes through WebGPU only, never CUDA or ROCm** (ADR-0007). The GPU model is the fp32 export with int32 `tokens` (the plugin aborts on int64 inputs; fp16 gives NaN on it), run by `KokoroSessionRunner` with inputs built exactly as KokoroSharp builds them (`KokoroInputs`). Every GPU clip passes `KokoroOutputCheck` or synthesis falls back to the CPU for the run (`KokoroRunnerChain`). The CPU model revision must stay unchanged so cached audio stays valid; the GPU's names the device.
- **Phonon runs through Gradium's C library only** (ADR-0009): `PhononTtsProvider` calls `libptts_ffi.so` through function pointers, one call at a time behind its gate, on the CPU. The library and model come from `tools/setup-phonon.sh` (pinned runtime commit, model and voice revisions, SHA-256 per file) or, for the library, from beside the application in a release; the app never builds or downloads them. Its audio is not repeatable byte for byte, which the cache tolerates (clips are synthesised once; timing is keyed by PCM hash). Each engine keeps its own voice setting (`PhononVoiceId`, default Maeve; `KokoroVoiceId`), and a restored position's voice from another engine is dropped. `ServiceRegistry.SpeechProvider` is the one engine in use; the voice list and the coordinator both take it.
- **The reader's annotations are their work, not narration** (ADR-0014). Kept by `ReviewAnnotationStore` (Pdf project) in `$XDG_DATA_HOME/rail-narrator/annotations/<sha256>/`: `annotations.json` in Core's format (written by `ReviewAnnotationJson`, held to Core's `ExportJson`/`ImportJson` by tests) and `links.json`, Rail Narrator's links to the narration by `NativeId` (Core's model has no field for them). Writes are atomic; a file that cannot be parsed is set aside, one that cannot be read is never saved over, and either is a lasting notice (`ShowLastingNotice`). Painting draws `AnnotationLayer`'s deep copy, never the live objects that undo actions change. They touch no cache key, generation or version constant. The PDF is changed only by exporting a copy; `NullAnnotationStore` stays Core's store. "What was just read" is `ReviewTarget.Find` (the reading unit holding most of the last cue's anchors; boxes from `PageTextCache`, never a union of anchors), and edits go through `ReviewSession` (Core's undo actions plus links, a sentence across a page break one annotation per page as a group). Annotate mode (Ctrl+E) marks text by hand through `MarkupDrag` (starts only on a line of text) and `ReviewTarget.ForRange`, whose quote goes through `PageQuote` (ligatures and PDFium's line-end hyphen marker resolved as `ReadingUnitBuilder` does; never the raw page text). Annotation keys (N, H, Ctrl+Z, Delete, Ctrl+E, 1–5 in annotate mode) are handled in `MainWindow.HandleReviewKey`, not as window key bindings, which would take a text box's own undo. A revised PDF (same path, other hash, found through `index.json`; or a PDF chosen by hand) gets the earlier version's notes through `ReviewCarryOver`, by their quoted words only (letters and digits compared); anything else is kept not placed (`unplaced.json` and `unplaced-links.json`, by the page it would go on) for the reader to place as before or discard. Copies get fresh ids. Do not add placement by position or by near match; read the earlier version with `ReviewAnnotationStore.Peek`, never `Load`, which sets unreadable files aside.
- **PortAudio's C `long` is `CULong`** (`PortAudioNative`): eight bytes on 64-bit Linux, four on 64-bit Windows. A `nuint` or `ulong` there reads garbage frame counts and flags in the callback on Windows. On Windows only WASAPI devices are offered (PortAudio lists each device once per host API, and MME's timing is useless to the media clock), and a stream is opened with `paWinWasapiAutoConvert`, falling back to a plain open. `PortAudioAbiTests` pins the struct layouts.
- **No colon in a file name.** Cache ids are `rn1:<hex>`; Windows refuses `:` in a path component, so `DiskSpeechAssetStore.DirectoryName` replaces it there (and only there, to keep Linux caches).
- **Host services are supplied, not inherited from Core.** Core's `AppConfig` hard-codes `~/.config/railreader2`; this app uses its own XDG directories (`XdgPaths`) and an inert `NullAnnotationStore`. Highlights are transient overlays and must never be written into the PDF.
- **Claude is a second transport for maths, not a second pipeline** (ADR-0010; settings `MathLlmProvider`, `VlmProvider`, default `OpenAiCompatible`). `ClaudeMathInterpreter` and `ClaudeMathVerbaliser` share the prompts, the validators and `MathTranscriptionReading` with the OpenAI-compatible clients, so a prompt or validator change still means one version bump; the vision transcriber uses Core's `AnthropicVlmClient`. `ClaudeMessages` is the one place that builds a Messages request: it sends no sampling parameters and no thinking switch (current models reject both; `MathThinking` sets `output_config.effort` instead), drops an optional field a model or gateway refuses, and asks for Anthropic's refusal fallback only against Anthropic's own API. A repair is a new request carrying the rejected answer, never a continued conversation, which would have to replay thinking blocks. Choosing Claude is the configuration (address optional, model defaults to `ClaudeEndpointSettings.DefaultModel`, a key not given is the SDK's to find), so keep the note and the dialogue text that say passages go to Anthropic.
- **The formula model reads display equations only, each from a crop of its own, and its LaTeX is checked against the page** (ADR-0011). PP-FormulaNet_plus-M (`PpFormulaNetRecogniser`, CPU, the decoding loop inside the ONNX graph, so no token probabilities) is used when its two files are installed and `UseFormulaModel` is on. `MathLlmEvidence` (`Image`, `Formula`, `Both`; default `Both`) decides what the interpreter is given for a passage with a display equation; `Formula` sends no image at all, so a sentence with maths in its line, which has no formula to transcribe, is then interpreted from its text alone. The crop is the equation's bounds with no padding above or below (`MathInterpretationResolver.FormulaCrop`): the interpreter's padded crop takes in a neighbouring line's ink, which the model transcribes too. `FormulaImage` and `PillowResample` reproduce the reference pipeline's image byte for byte (Pillow's 8-bit arithmetic; tests pin digests) — do not "simplify" the scaling. `FormulaTextLayerCheck` compares Greek letters and decimal numbers with the text layer: a one-for-one letter slip is settled by the page, anything else is a noted disagreement, and a transcription that still disagrees is never read by rule (`FormulaMathReader`), only given to the interpreter with the note. With no language model the resolver is built without an interpreter and display equations are read by rule (`ServiceRegistry.ResolvesMathsLate`, not `MathInterpreter is not null`, says whether maths is resolved during playback). A request without a formula is built and keyed exactly as before, so `MathInterpretationPrompt.Version` did not move; change the prompt's formula paragraph → bump `RecognisedFormula.EvidenceVersion`; change the image preparation, decoding or output checks → bump `PpFormulaNetRecogniser.PipelineVersion`.
- **A saved narration carries its own plan and is played as recorded** (ADR-0012). `paper.narration` beside the PDF (`SavedNarration`, a zip: manifest, plan, and per passage its `SpeechAsset` and Opus audio) is tied to the PDF's content hash; `MainViewModel.LoadDocumentAsync` then takes the plan from it instead of planning, opens without reading the pages (`ExtractBehindAsync` reads them afterwards, for notes; `_snapshot` is null until then) and gives it to the coordinator as an `IRecordedNarration`, which is consulted before the engine (`PrepareFromRecordingAsync`; the engine is asked for lazily, `EngineAsync`, so none need be installed). A passage is served only with the script it was recorded with, and a voice change drops the recording. Narrating is `NarrationCoordinator.NarrateAllAsync` on a coordinator of its own with `NullAudioTransport` (`NarrationJob`): the same preparation as playback, so do not write a second synthesis path. `NarrationAudio` records each clip's length and the codec's delay because timings are in samples of the clip; a decoded clip of another length is refused. A maths endpoint that cannot be asked stops the job unless told otherwise. `HeadlessNarration` runs before Avalonia starts and must not touch it. Change the file's layout → bump `SavedNarrationManifest.CurrentFormat`.
- **An endpoint that cannot be asked is said, once.** A refused key or an exhausted quota makes every equation fall back to its rule reading, which sounds like worse interpretation. An interpreter reports why it is unavailable (`UnavailableReason`) or why a request failed at the endpoint (`MathInterpretationResult.EndpointProblem`; not for an answer that was merely rejected), `MathInterpretationResolver.EndpointProblem` raises it per passage, and `MainViewModel` shows one notice per reason. The words come from `EndpointRefusal` (status code and host), never from the response body, which may echo part of the key.
- **Providers are registered only when implemented and configured**, so the UI never offers an inert selector. An API key is either read from an environment variable named in settings or stored in `settings.json` (`MathLlmApiKey`, `VlmApiKey`; the stored key wins); `SettingsStore.Save` writes the file mode 0600 from creation, so keep every write going through it, and never log, display or put a key in a message (`EndpointProbe` reports refusals without it).

### Settings dialogue

`SettingsWindow` / `SettingsViewModel` (File ▸ Settings…, Ctrl+,) saves each change as it is made through `MainViewModel.PersistSettings` (read, change, write, so the main window's own preference saves survive; it waits for those still queued). The main window's own preferences go through `PersistPreference` to `SettingsStore.UpdateLater`, written in order off the UI thread and flushed on closing; a change passed to it captures its values rather than reading the view model later. Reading preferences apply at once by updating only those fields of `ServiceRegistry.CurrentSettings`; engines (speech, maths, layout, filters) are built once in `ServiceRegistry.Create`, so their changes apply after a restart, which the dialogue offers (it relaunches with the open document after the position is saved). A new setting: add it to `RailNarratorSettings`, to the dialogue, and, if it applies at once, to `SettingsViewModel.SaveLive` and to the fields `EngineSignature` leaves out.

### Look and feel (follows RailReader2)

Fluent, light by default; dark and the text size (`DarkMode`, `UiFontScale`) apply live through `App.ApplyAppearance`, and a window opened later takes the main window's `FontSize`. Colours come from Fluent's theme brushes or the theme dictionaries in `App.axaml` (`ReadingCanvasColor`, `OverlayCardBrush`, `OverlayVeilBrush`); don't hard-code a colour that must read in both themes. Icons are Lucide `StreamGeometry`s in `Assets/Icons.axaml` drawn by `Controls/Icon` (copied from RailReader2; sized from the inherited font size, so they scale with the text); an icon button gets `AutomationProperties.Name` and its shortcut in the tooltip. Button classes `toolBtn`, `borderless`, `active`, `primary` and `toolSep`/`overlayCard` are defined in `App.axaml`.

The sidebar (F6) is on the left, as RailReader2's: an accordion (`MainWindow.SetUpSidebar`, one section open, its row starred) of Outline, Script, Maths review and Notes; width, visibility and open section are reader preferences in settings (excluded from `EngineSignature`). The Outline is the PDF's bookmarks (`PageRasterSource.Outline`, read off the UI thread at open; pages zero-based). Choosing a heading while playing seeks there; otherwise it shows the page and sets a pending start that the next Play consumes and any other seek clears (`MainViewModel.StartReadingAsync`). Its `SelectionChanged` handler is safe because nothing syncs the tree to the reading; the script list's rule (seek only through `SelectedIndex`) still stands. Status-bar notices (`ShowNotice`) take the place of the status line with one action; raise one per event, not per snapshot. The section name is the heading before the reading on the page being read (`OutlineSections`, by the heading's words in the plan), by page otherwise. A file dialogue is opened through `MainViewModel.InPicker`: the portal's dialogue is not modal, so the window drops keys and typed text while one is up. Start-up builds `ServiceRegistry` off the UI thread behind `SplashWindow` (`App.StartAsync`; keep `ServiceRegistry.Create` free of Avalonia), with `StartupErrorWindow` if it throws. `MainViewModel.CloseDocumentAsync` saves the position, stops and returns to the welcome screen; `RecentDocumentsStore` keeps the recent list and thumbnails. A PDF dropped on the window opens through `LoadDocumentAsync` (`MainWindow.SetUpFileDrop`; Avalonia 12's `e.DataTransfer.TryGetFiles()` and `TryGetLocalPath()`).
